# Поиск дублей объявлений — Avito ML Cup 2025

Решение задачи [«Поиск дублей»](https://ods.ai/competitions/avitotechmlchallenge2025_2),
апрель–май 2025: для пары объявлений предсказать, является ли кандидат дублём базы.
Пара описывается 58 признаками сходства, поверх них учится LightGBM. Обучение — 1 879 555
пар, дублей 5.6 %.

| | PR-AUC | ROC-AUC | MAP |
|---|---|---|---|
| Жаккар заголовков, без обучения | 0.152 | 0.757 | — |
| Это решение, OOF на 5 фолдах | **0.496** | 0.906 | 0.941 |

MAP соревнования на открытых данных вырождена: 2.6 кандидата на базу, дубль есть у 7.4 %
баз, случайный скор даёт 0.87. Закрытый тест участникам не выдавали, сравнить с
лидербордом нельзя, поэтому основная метрика здесь — PR-AUC.

## Решение

* **Признаки** ([`features.py`](src/features.py)) — совпадение и Жаккар заголовков и
  описаний по токенам и символьным n-граммам, containment, общий префикс, отношение длин,
  Жаккар по числам, `json_params`, цена, гео, категории.
* **Тексты** ([`text.py`](src/text.py)) — 71 % кириллических токенов обфусцированы
  латиницей (в `Куpткa` латинские `p` и `a`). Для сравнения строк азбуки сворачиваются,
  перед подачей в трансформер гомоглифы чинятся.
* **Эмбеддинги** ([`embeddings.py`](src/embeddings.py)) — `rubert-tiny2` считается один раз
  на уникальный текст: уникальных 2.66 млн против 3.76 млн сторон пар. Пары адресуют
  таблицу индексами.
* **Двухбашенная модель** ([`models.py`](src/models.py)) — обучаемая проекция над
  замороженным энкодером. Косинус сырых эмбеддингов измеряет смысловую близость, а нужна
  близость в смысле дубля: два похожих пуховика близки по смыслу, но это не дубли.
* **Фотографии** ([`images.py`](src/images.py)) — хеш главного фото не совпал между
  сторонами ни разу на 1.88 млн пар: перепост пережимает файл заново. Сами снимки
  работают — перцептивный хеш находит буквальный перепост, CLIP — пересъёмку того же
  товара.

## Валидация

`GroupKFold` по `group_id`. При случайном разбиении по строкам 45 % объявлений валидации
(304 051 из 674 800) уже были в обучении, потому что одно объявление стоит в кластере и как
база, и как кандидат. На одних и тех же признаках это даёт 0.589 PR-AUC против 0.469 на
`GroupKFold`.

Вклад блоков признаков, абляция на одном фолде:

| Убрано | Потеря PR-AUC |
|---|---|
| текстовое сходство | 0.066 |
| цена, фото, гео | 0.023 |
| скор башен | 0.021 |
| сравнение фотографий | 0.015 |
| эмбеддинги | 0.005 |
| `json_params` | 0.004 |

Основа решения — сравнение строк: без него потеря больше, чем от всех остальных блоков
вместе. Обучаемая проекция ценнее сырого косинуса: 0.021 против 0.005.

## Что не сработало

**Кросс-энкодер** ([`cross_encoder.py`](src/cross_encoder.py)). Башни кодируют стороны
независимо, поэтому «iPhone 11, 256 ГБ» и «iPhone 11, 128 ГБ» дают почти одинаковые
векторы. `rubert-tiny2`, дообученный целиком на обеих сторонах пары через `[SEP]`, дал
0.300 PR-AUC против 0.496 у бустинга. Кривая смеси по рангам монотонна: оптимум — чистый
бустинг. Кросс-энкодер видит только текст, а кандидатов внутри кластера различают цена,
категория и гео.

**Триплеты** ([`triplets.py`](src/triplets.py)). Вместо парной контрастной функции —
triplet margin loss с отбором трудных негативов. Триплетная башня признаком в бустинге
дала 0.459 против 0.479 у контрастной — ровно уровень «без башни». Негативы оказались
слишком трудными:
из 105 тыс. отобранных 30 136 пришли из той же базы, 74 903 — из той же группы `param2`,
случайных и межкатегорийных ноль.

**Наивный стекинг.** Скор башен, посчитанный на их же обучающих данных, снижает PR-AUC до
0.400 — хуже, чем вовсе без башен. Отсюда вложенная схема: обучающие строки получают скор
по внутренним фолдам.

Полные выводы прогонов — [`reports/results.json`](reports/results.json) и
[`reports/results_triplet.json`](reports/results_triplet.json).

## Запуск

Загрузить [`notebooks/avito-duplicates.ipynb`](notebooks/avito-duplicates.ipynb) на Kaggle,
подключить [датасет соревнования](https://www.kaggle.com/datasets/chuvirla/avito-ml-cup-default-dataset)
и наборы с фотографиями ([train](https://www.kaggle.com/datasets/uhtiblya/train-images),
[test](https://www.kaggle.com/datasets/uhtiblya/test-images)), включить GPU, Save & Run All.
На выходе — `submission.csv`, `results.json` и таблица эмбеддингов фотографий. Флаг
`QUICK_RUN = True` прогоняет одну часть обучающих данных без теста. Ноутбук самодостаточный,
репозиторий для запуска не нужен; тот же код модулями лежит в [`src/`](src/).
